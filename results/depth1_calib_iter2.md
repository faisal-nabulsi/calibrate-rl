# depth-1 chain calibration — iter2 edits

**Context.** iter2 readout: 0/47 in-band, mean goldilocks-frac 0.05. Composite
pass = P(feeder correct) x P(target correct), so a chain only lands in-band when BOTH
the feeder and the target step are individually tractable AND the composite answer is
diverse. The per-chain readout n was tiny (~5 rows/chain), so the reliable signal is
the EXTREMES (pass <=0.2 = genuinely TOO_HARD; >=0.9 = TOO_EASY); mid-band
LOW_DIVERSITY flags at pass 0.3-0.7 (count_pythagorean 0.475, point_rotation 0.5,
multi_constraint_square 0.525, ...) are mostly small-sample top-3 noise on chains that are
already near-band, so I left those alone to avoid destabilizing them.

The lever I own is the TARGET step (shared adapter + per-chain knob) and the fed-value
filter; feeders are depth-0 atoms I must not touch. So I eased/hardened/diversified the
TARGET, which dominates difficulty when it is intrinsically hard (telescoping, digit
counting, big-base modexp).

All edits are gate-clean: static_checks is 41/47, identical to the pre-edit baseline,
and the 6 remaining fails are the PRE-EXISTING documented thin-feeder dedupe chains at
their exact baseline survival (alternating_cubes 0.885, box_diagonal 0.645, complement->tele
0.885, ordered_triple->digit 0.820, prime_power 0.820, telescoping->perfsq 0.825) -- none
worsened. Atom-equivalence (4) + full calibrator suite (13) pass; no atomic generator/knob
touched.

## What changed

### EASE -- TOO_HARD targets (the bulk of the 0/47)

1. Telescoping target (_a_telescoping_N), 6 chains -- knob gap now INCLUDES 1
   (was {2..7}). gap=1 collapses sum 1/(k(k+1)) to V/(V+1) -> answer 2V+1 (clean single
   step); gap>=2 stays the messy partial-fraction reduction. Kept a wide gap set
   ({1,2,3,4,5} or {1,2,3,4,5,6}) so the low-diversity feeder complement_prob_mn does not
   collapse dedupe -- complement->tele holds at its baseline 0.885. Chains: complement_prob_mn,
   constrained_divisor_count, frobenius_stamps, poly_remainder, rate_closing, perfect_square_divisible.

2. constrained_digit_count target (_a_digit_target), 5 chains -- range now starts at a
   CLEAN lower bound (lo in {1,100}) with a BROAD span set {149..999}, replacing the old
   arbitrary [500,4500)+[800,3500) windows. Counting digit-sum==V over [1,N) is a clean
   combinatorial task (stars-and-bars), vs. an unanchored [1500,4000) window which forces
   error-prone enumeration with inclusion-exclusion on both bounds -- that mismatch was why
   all 5 sat at ~0 pass. The broad span set restores answer diversity (top-3 0.13-0.26).
   Chains: arith_series_sum, arith_term_filter, complex_modulus_power, equalization_fraction,
   ordered_triple_constraint.

3. modular_exponent (base) target (_a_modexp_base), 6 chains -- knob k->2 (single squaring,
   fewest meaningful steps) and the shared fed-base ceiling lowered 10^12 -> 5000. V^k mod m
   on a ~10^12 base is an intractable too-hard ghost (sec5: big numbers teach tedium); capping
   V keeps the modular-reduction step learnable. This is a FILTER bound (which feeder outputs
   feed the target), not the difficulty knob. m widened to [50,2000] for answer spread.
   Chains: algebraic_system_2eq, distinct_product_count, divisor_sum_filter,
   inclusion_exclusion_3set, infinite_product_exp, mean_removal.

4. algebraic_system_2eq target (_a_algebraic_x), 2 feeder-hard chains -- y,z->[3,12],
   coef->[1,4] (smaller linear-system constants = lighter arithmetic on the solve-for-y,z
   step), for polynomial_sign_intervals and vieta_pair_count (both feeder-limited TOO_HARD).
   Mid-band algebraic chains left untouched.

### HARDEN -- TOO_EASY chains (more constraints)

5. three_number_system->inclusion_exclusion_3set (0.917) -- added a per-chain nsets knob set
   to 3, restoring the third divisibility set (one more inclusion-exclusion term). _a_ie3_U
