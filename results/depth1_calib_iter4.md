# depth-1 calibration — iter4 edits & rationale

Baseline: 2/47 in-band, mean goldilocks-frac 0.08, 45 flagged (mostly TOO_HARD).
All edits are chain-layer only (adapters, chain knobs, chain recomputers). Atom-equivalence
test PASSES (no depth-0 atom touched). Full 47-chain gate replicated locally via
`gen_clean --n 40` + `check_dataset`: **0 gold mismatches / 1651 rows, 0 SEVERE
(top3<=0.50, dd>=0.40) chains.**

## Grounding (sampled V/answer distributions before editing)
The readout per-chain `top3` (0.4-1.0) is small-n (n=2-10) noise; the binding signal is the
**mean pass** and **build-time answer diversity**. Sampling revealed difficulty drivers per target:

- **modexp** `V^k mod m`: hard when the *fed base V is large* (divisor_sum V~1736, ie3 V~344 ->
  squaring a 4-digit number is an intractable big-number ghost, S5). A **smaller modulus** forces
  the *reduce-base-first* method (1736 mod 50 = 36, then 36^2) -> tractable + still diverse.
- **telescoping** `sum 1/(k(k+gap))`: reduced `m+n` is astronomically large (medians 1e4-1e8!)
  because `gap` is the partial-fraction count. **gap is the knob**, not V.
- **constrained_digit**: count of ints in `[lo,hi)` with digit-sum V -> step count = `span`
  (#integers scanned). spans up to 649 -> too hard.
- **equalize**: chains are .1-.36 though feeders are EASY (complex_eq atom 92%, roots 64%) -> the
  `(1-fn)/V` fraction reduction is the bottleneck, not the feeder. Simplify `fn`.

## Edits

### Eased (TOO_HARD -> fewer steps/constraints)
- **modexp** (smaller modulus -> reduce-base-first; k->2 = pure squaring): divisor_sum_filter
  m->[30,200]; inclusion_exclusion_3set m->[30,200]; infinite_product_exp m->[30,200];
  mean_removal k[2,4]->[2,2], m->[30,300]; algebraic_system_2eq k[2,3]->[2,2].
- **telescoping** (drop big gap -> small m+n): frobenius gap->[1,2]; complement_prob gap->[1,2];
  poly_remainder gap->[1,2,3].
- **constrained_digit** (fewer integers to scan): all 5 span->[149,199,249,299] (was up to 649,
  median 399->224), lo->[50..400]. NOTE: counts are low-cardinality, so span<~150 collapses answer
  diversity below dd>=0.40 -> 149 is the *diversity floor*; removes the 449/549/649 killers while
  staying gate-legal. A modest (not full) ease by necessity.
- **ie3 -> single divisor** (new optional `nsets=1`: `V//a`, no inclusion-exclusion): for the
  feeder-limited targets vieta_sumcubes (was 3-set!), lattice_points_circle, continued_fraction.
  Chain pass now floors at the feeder's own rate instead of dying on an IE step over a hard feeder.
- **multisquare**: alternating_cubes - dropped the 2nd (last-digit) constraint (`last` now optional
  in the adapter) -> single divisibility count. Was .05 with both constraints on a huge V.
- **equalize** (global `fn` simplify): cut denom-7/8 fractions -> 12 options with denom <=6,
  cleaner single-step reductions. Helps all 5 (4 need easing); geo_first (.525) drifts up slightly.
- **algebraic** (cleaner elimination): polynomial_sign_intervals coef[1,4]->[1,3] (+ y,z->[3,18]
  to restore answer diversity, a widen-non-fed-input move); vieta_pair_count coef[1,4]->[1,3].
- **complement** (per-chain `thr` knob; smaller thr -> fewer rolls = fewer iteration steps):
  constrained_subset & sum_of_squares -> low thr [[1,2],[3,5],[2,3]].

### Hardened (TOO_EASY -> more steps/constraints)
- **ie3**: three_number_system nsets 2->3 (was 1.0).
- **telescoping**: constrained_divisor_count gap[1,2,3]->[2,3,4] (was .6; drops trivial gap=1).
- **complement**: digit_count_bigprod -> high thr [[3,4],[4,5],[5,6]] (was .604).
